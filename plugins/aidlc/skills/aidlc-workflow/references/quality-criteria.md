# 品質基準リファレンス

## AC（受入基準）品質基準

すべての AC は以下の3条件を満たすこと:

| 条件 | 定義 |
|---|---|
| **具体的** | 数値・条件・状態が明記されている |
| **検証可能** | テストで合否が判定できる |
| **一意** | 読む人によって解釈がブレない |

### NG/OK 例

| NG | OK |
|---|---|
| レスポンスが速い | 一覧画面の初期表示が2秒以内 |
| 適切なエラーメッセージを表示する | 入力が空の場合、フィールド下部に赤字で「必須です」と表示する |
| ユーザーが簡単にログインできる | メールアドレスとパスワードで30秒以内にログインできる |

## 暗黙の要件チェックリスト（6カテゴリ）

各カテゴリについて「必要」「不要」を判断し、必要な場合は機能要件に追加する。

| カテゴリ | チェック観点 |
|---|---|
| **認証・認可** | ログインは必要か？ ユーザー種別ごとの権限は？ |
| **データライフサイクル** | CRUD すべて必要か？ 保存期間は？ |
| **通知・フィードバック** | 操作結果の表示方法は？ 非同期完了の通知は？ |
| **エラーハンドリング** | 失敗時にユーザーに何を表示するか？ |
| **管理機能** | 管理者向けの機能は必要か？ |
| **外部連携** | 他サービスとの連携は？ インポート/エクスポートは？ |

## 異常系・エッジケースパターン（5パターン）

各ユーザーストーリーについて以下を検討する:

| パターン | 例 |
|---|---|
| **不正入力** | 空、形式不正、範囲外、文字数超過 |
| **リソース不在** | 対象データが存在しない、削除済み |
| **権限不足** | 認可されていないユーザーのアクセス |
| **状態不整合** | 同時操作、処理済み項目の再処理 |
| **外部依存障害** | API停止、タイムアウト |

重要な異常系 → AC に含める。軽微な異常系 → Phase 4 で AI の裁量に任せる。

## 矛盾検出の対象

要件セット全体を分析し、以下の矛盾・曖昧さがないか確認する:

- スコープの不一致（ある要件では In Scope、別の要件では暗黙に Out of Scope）
- 優先度の矛盾（依存関係にある要件の優先度が逆転）
- 前提条件の衝突（同時に成立しない前提を含む要件）
- 用語のブレ（同じ概念に異なる用語を使用）

矛盾が発見された場合は、人間に提示し解消されるまで次のステップに進まない。
